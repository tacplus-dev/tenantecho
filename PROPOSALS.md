- **fleet-seatrials: name the target tenant in tenantecho calls** (2026-10-28, #5): since #5, `PingRequest.tenant` (2) and `PingPigeonRequest.tenant` (3) are the route fields, and a call with an empty or malformed one is refused with `INVALID_ARGUMENT` before it is sent. The seatrials client sends neither (tacplus-dev/fleet-seatrials `client/cmd/seatrials/main.go`, `ping` and `pingPigeon`). When that fleet moves to tacplus 2.5, it should send the credential's tenant tid, and maybe add a `-tenant` flag to show that a call naming another tenant is refused (`PERMISSION_DENIED`). Its `build/proto/services/tenantecho.proto` copy also has to follow this one.
- **README examples use tenant names, not tids** (2026-10-28, #5): the README and tests show `tenants/acme`. Since 2.5, a tenant's namespace is `/tenants/<tid>` (8 characters of `[0-9a-z]`), and the route field must be a tid. The examples should use a tid, so they match what a caller now sends.
- **Floor 2.6 and a pinned build image, so plain `tacplus` can run the gates** (2026-10-29, #5): tacplus-dev/tacplus#193 replaced the `tacplus:X.Y` compiler image (no `go`) with `build:X.Y`, whose `tacplus` runs the version pinned in `tacplus.lock`, but only from 2.6.0 (tacplus-dev/tacplus#213), and the launcher refuses a pin from another line. `tacplus:2.5` (2.5.1 today) still cannot generate Go. Once 2.6.0 is out: set `tacplus: "2.6"`, pin it (`tacplus pin`, `tacplus.lock`), and run the gates in `build:2.6`. The looper's `tacplus` wrapper runs `tacplus/tacplus:<floor>`, so it has nothing to run for 2.6 until tacplus-dev/looper changes (tacplus' own PROPOSALS.md; tacplus-dev/looper#15 removes the wrapper). Update 2026-11-06 (#5): plain `tacplus` 2.5.11 now generates Go, so the gates no longer need this; what is left is the pin (a reproducible compiler) and the 2.6 features (v2.6.0 is out). Update 2026-11-06 (nightly scan): the floor and the pin are now bug #9 (2.6 is the latest released line; the gates pass on 2.6.1); what is left here is using 2.6 features.
- **looper-trace does not see tenantecho's handlers** (2026-11-03, #8): `looper-trace check` reports `pass (0 handlers, 0 findings)` here, before and after #8, so it misses `TenantEcho.Ping` and `PingPigeon` (`func (s *Server) X(ctx, *servicemanager.Caller, *pb.XRequest)`, the chassis' handler shape with a caller argument) and would not have caught the dropped `trace_id` #8 fixed.
